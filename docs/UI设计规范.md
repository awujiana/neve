# Névé UI 设计与交互规划

> 版本：v0.1 | 状态：设计基线（未实现）| 最后更新：2026-10-27
> 关联文档：[设计文档（PRD）](./设计文档.md) · [架构文档](./架构文档.md) · [主题令牌草案](../config/ui-theme.toml)

## 1. 设计目标

Névé 是管理器，不是播放器。界面应帮助用户快速回答「检测到了哪些播放器」「哪些脚本或配置需要处理」「这次操作会改动什么」，把 MPV 文件和配置的复杂性转成可预览、可撤销的操作。

- **清楚优先**：状态、来源、目标路径与操作影响必须易读；液态玻璃用于建立层级，不得成为文字底板的干扰纹理。
- **可逆操作**：写入播放器目录或系统设置前显示目标与备份信息；完成后提供结果摘要和恢复入口。
- **一致导航**：常驻侧栏承担功能切换；页标题、主要动作和当前播放器上下文在内容区保持稳定。
- **渐进披露**：常用操作在主界面直接可见；高级配置、路径和冲突来源放入详情或展开区。
- **原生克制**：保留 GPUI 原生桌面窗口的清晰边界、键盘操作与系统行为，不仿制浏览器页面或媒体播放器的播放控件。

## 2. 信息架构与页面

| 页面 | 主要内容 | 主操作 | 关键状态 |
|---|---|---|---|
| 概览 | 已检测播放器数量、需注意事项、最近操作、快捷入口 | 重新扫描 / 添加播放器 | 扫描中、未发现、扫描失败、正常 |
| 播放器 | 播放器/整合包列表、类型、版本、可执行文件与配置目录 | 设为常用 / 打开位置 / 更新 | 可用、版本未知、路径缺失、更新可用 |
| 脚本 | 已安装与可管理脚本、依赖、来源、版本 | 安装 / 启用 / 停用 / 更新 | 未安装、已安装、依赖缺失、更新可用、冲突 |
| 皮肤 | uosc 主题与 OSC 皮肤、预览和当前提供者 | 预览 / 应用 / 切回 | 当前使用、可应用、提供者冲突 |
| 配置 | mpv.conf、input.conf、脚本配置与冲突清单 | 编辑 / 检查冲突 / 恢复 | 已修改、冲突、备份可用 |
| 备份与同步 | 操作批次、来源与目标、文件差异、恢复记录 | 预览同步 / 执行 / 恢复 | 待确认、完成、部分跳过、可恢复 |
| 设置 | 外观、语言、音效、托盘、数据位置与系统集成 | 保存或即时应用 | 当前值、系统跟随状态、路径状态 |

播放器上下文选择器用于脚本、皮肤和配置页。涉及多播放器操作时，明确标出来源包与每个目标包；不得依赖用户从页面位置推断目标。

## 3. 主窗口布局

- **顶栏**：应用名称/当前页标题、可选的全局搜索或帮助入口、昼夜主题开关。窗口系统按钮沿用平台标准行为。
- **侧栏**：概览、播放器、脚本、皮肤、配置、备份与同步、设置。当前页通过背景/标记和文字共同表达，不只靠颜色。
- **内容区**：页标题与一句说明、主要操作、筛选/工具、结果列表或编辑区域。列表在空状态时给出下一步动作。
- **详情面板**：用于展示路径、来源、版本和操作影响；窄窗口时改为独立详情页或覆盖面板，不压缩主内容到不可读。
- **操作反馈**：成功/失败提示包含可理解结果；长操作显示进度与可取消状态，结束后保留差异和恢复入口。

窗口最小尺寸应先以常见 1280×800 工作区完成布局验证。较窄窗口优先折叠侧栏与将详情改为单独视图，不隐藏关键状态和撤销入口。

## 4. 液态玻璃视觉语言

### 4.1 层级与材质

1. **背景层**：浅色为雾白到冰蓝的低饱和渐变；深色为蓝黑/石墨色。可选背景图必须经过遮罩，维持正文对比度。
2. **主工作层**：内容区域使用高不透明度表面承载文本与表格；避免重模糊背景造成长时间阅读疲劳。
3. **浮层**：菜单、对话框、侧栏选中容器和信息卡片使用半透明表面、细亮边、柔和阴影与有限背景模糊，体现轻微折射感。
4. **强调层**：冰川蓝用于主操作、选中态和焦点；琥珀/红色只用于警告/错误。操作状态始终配文字或图标。

玻璃质感由半透明填充、内侧高光边缘、柔和投影与背景模糊共同构成。不要给每个列表行、按钮和标签都加玻璃、光晕或渐变；密集内容区保持稳定的不透明底色。玻璃强度允许「柔和 / 标准 / 清晰」预设，默认标准。

### 4.2 昼夜主题开关

参考 [Animated Day/Night Theme Toggle](https://codepen.io/xnmiuhbp-the-sans/pen/ZYeMYOq) 的太阳/月亮滑块、云层退场和星点出现。将其作为交互意象而非整页视觉模板：将云、星、日/月收敛到适合桌面工具的紧凑控件，保持侧栏及内容布局稳定。参考原型的转场约为 300ms；本项目目标为 240–320ms 的平滑转场，最终以 GPUI 实现与窗口性能验证为准。

- 浅色状态显示暖金太阳、淡云与清透蓝色轨道；深色状态显示银月、星点与蓝黑轨道。
- 点击或键盘激活时，滑块横移，日/月形态切换，云与星作轻量位移；页面语义色同步渐变。
- 开关提供可访问名称（如「切换到深色主题」）和明确当前状态；支持 Tab 聚焦与 Enter/Space 操作。
- 提供「跟随系统」作为设置项。快捷开关只在浅/深之间切换；点击后由用户显式设置覆盖系统跟随，并在设置中可恢复跟随。
- 尊重系统减少动态效果；减少动效时直接变更状态并保留太阳/月亮的静态差异。

### 4.3 色彩与可读性

初始主题令牌见 [ui-theme.toml](../config/ui-theme.toml)。它们是设计参考值，尚未绑定运行时代码。正文、次级文本、边框、焦点、成功、警告、错误都使用语义令牌，不在页面中散落硬编码颜色。实现验收需检查文本对比度达到 WCAG 2.1 AA（普通文字至少 4.5:1），包括玻璃底板与背景图组合。

## 5. 交互与状态规范

- **首次运行**：先展示扫描进度，再显示检测结果；未检测到时提供「选择播放器目录」与重试。扫描失败需给出可理解原因，不伪装为空列表。
- **扫描**：扫描在后台运行；结果逐步或完成后呈现，取消/重试状态明确。`--version` 探测失败显示「版本未知」，不阻塞主要列表。
- **写入/同步**：执行前预览目标、将新增/覆盖/跳过的文件和备份位置；存在同名不同版本时要求选择冲突策略。完成页提供摘要及恢复入口。
- **编辑配置**：保留原始注释和顺序；冲突高亮但不阻止用户保存。提示实际生效值、定义来源与行号。
- **破坏性或系统操作**：文件关联、自启动等操作说明作用范围与撤销方式；不在未告知时更改默认应用。
- **空、加载、错误状态**：每个主要页面都定义空状态、加载状态、错误状态；空状态包含下一步入口，错误状态包含重试或诊断信息。
- **键盘与焦点**：导航、列表、弹窗、主题切换均可键盘访问；焦点环在浅/深主题和半透明浮层上都清晰。

## 6. 动效与性能

| 场景 | 规划时长 | 行为 |
|---|---:|---|
| 主题切换 | 240–320ms | 色彩渐变与开关图形同步，避免布局跳动 |
| 悬停/按下反馈 | 100–160ms | 轻微亮度/位移，不放大影响邻近布局 |
| 页面与面板出现 | 160–220ms | 淡入或小幅位移；首次加载不延迟交互 |
| 列表更新 | 120–180ms | 仅在减少动态效果关闭时做有限过渡 |

模糊和阴影要有统一成本上限。大面积背景模糊不可逐行重复；低端显卡或不支持模糊的窗口环境退回到不透明底色和细边框。动效不得承载唯一状态信息，也不得让操作反馈等待动画结束。

## 7. 主题设置草案

持久化到用户数据目录的 `settings.json`，下列为规划字段而非已实现 schema：

```json
{
  "theme_mode": "system",
  "glass_strength": "standard",
  "background_mode": "gradient",
  "list_density": "comfortable",
  "motion": "system"
}
```

字段约束：`theme_mode` 为 `system | light | dark`；`glass_strength` 为 `soft | standard | clear`；`background_mode` 为 `gradient | custom_image | solid`；`list_density` 为 `comfortable | compact`；`motion` 为 `system | full | reduced`。设置迁移需兼容未知字段并为缺失字段补默认值。

## 8. 实施顺序与待确认项

1. 在页面骨架阶段先落地主导航、播放器列表、空/加载/错误状态与主题语义令牌。
2. 验证浅/深主题、系统跟随和减少动效，再做太阳/月亮开关动画。
3. 在稳定色彩与层级后加入玻璃浮层；对照不透明回退检查对比度和性能。
4. 配置、同步与皮肤流程按 PRD 的写前预览、备份、冲突和恢复原则接入。

实现前需要在目标 Windows/GPUI 版本确认：系统外观变化通知、背景模糊能力、减少动态效果偏好读取、动画性能与高对比度支持。若框架不支持某项能力，保留等价语义和不透明视觉回退，不以浏览器 CSS 行为假定原生实现能力。
