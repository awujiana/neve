# Névé 设计文档（PRD）

> 版本：v0.3 | 状态：规划稿 | 负责人：awujian | 最后更新：2026-10-27
> 配套文档：[架构文档](./架构文档.md) · [UI 设计规范](./UI设计规范.md)

## 1. 背景与问题

MPV 内核播放器（mpv、mpv.net、Celluloid、IINA 及各类整合包）用户普遍面临：

- 播放器/整合包多套并存，配置与脚本各自为政，重复劳动严重
- 脚本（uosc 系）安装、启停、依赖管理全靠手动复制文件
- 视频文件关联、开机自启、托盘等系统级配置分散，无统一入口
- 缺少一个类似 PCL2（Plain Craft Launcher 2）的、开箱即用的图形化管理器

**产品定位**：面向所有 MPV 内核播放器的统一管理器，交互体验对标 PCL2。

## 2. 目标用户

| 用户类型 | 典型场景 | 核心诉求 |
|---|---|---|
| MPV 深度用户 | 维护多套整合包与脚本 | 脚本/配置跨包同步，减少重复劳动 |
| 普通播放器用户 | 只想换个好看的播放器 | 一键安装、一键文件关联、开箱即用 |
| 配置折腾党 | 反复调整按键与 mpv.conf | 可视化编辑、备份恢复、常用文本片段 |

## 3. 功能需求（P0/P1/P2）

### FR-01 播放器管理（P0，已部分实现）

作为 MPV 用户，我想要自动检测本机所有 MPV 内核播放器并统一管理，以便在一个界面完成安装、切换与更新。

- 检测：常见路径 / 注册表 / PATH 三路扫描（已实现于 `core::players`）
- 安装与更新：支持 mpv-Bingshan 整合包与 shinchiro/zhongfly 构建源

### FR-02 脚本管理（P0）

作为整合包用户，我想要一键安装/启停/更新 MPV 脚本（lua、uosc 系），以便不手动复制文件。

验收标准：

- Given 脚本仓库中存在某脚本，When 用户点击安装，Then 脚本文件与其依赖被复制到目标播放器的 `scripts/` 目录并在列表中标记为已安装
- Given 已安装脚本，When 用户点击停用，Then 仅修改配置中的启用状态，不删除文件
- Given 脚本存在依赖脚本，When 用户只勾选主脚本安装，Then 依赖被提示并默认一并安装

### FR-03 脚本跨包一键应用与配置同步（P1）

作为多整合包用户，我想要把某个脚本一键应用到其他整合包、把脚本配置一键同步到其他整合包，以便所有包保持一致。

验收标准：

- Given 脚本 A 已安装在整合包 X，When 用户选择"应用到其他包"并勾选整合包 Y，Then 脚本 A 的文件与配置被复制到 Y，且输出差异报告（新增/覆盖/跳过）
- Given 脚本 A 在 X 中的 conf 已修改，When 用户点击"同步配置到其他包"，Then 仅同步 conf 文件，且同步前对目标包的旧 conf 做时间戳备份，可一键恢复
- Given 目标包已有同名但版本不同的脚本，When 用户应用，Then 默认提示冲突并提供「跳过 / 覆盖 / 双份保留」三选项

### FR-04 外观定制（P1）

作为用户，我想要选择浅色、深色或跟随系统的主题，并调整背景、玻璃表面强度、列表密度和动效，以便界面符合个人偏好且内容始终清晰可读。视觉基线采用液态玻璃卡片与太阳/月亮昼夜切换控件；详细页面布局、色板和交互见 [UI 设计规范](./UI设计规范.md)。

验收标准：

- 主题模式提供「浅色 / 深色 / 跟随系统」；跟随系统时系统外观变化实时生效，手动选择不被系统覆盖
- 昼夜开关具有太阳、月亮、云层、星点的状态反馈；切换结果同时由文字或可访问名称表达，不仅依赖颜色
- 主题选择、背景来源、玻璃强度、列表密度、动效偏好均持久化；重启后恢复
- 背景与玻璃表面不得降低正文、状态、焦点指示的可读性；低透明度/无模糊回退仍保持层级清楚
- 列表密度提供舒适/紧凑预设；动效支持完整/减少两档并尊重系统减少动态效果设置
- 液态玻璃的模糊与透明在目标平台验证性能后启用；不支持时退化为不透明表面，不影响功能

### FR-05 数据管理（P1）

作为用户，我想要导出/导入数据，且便携版可连同数据一起移动、安装版可更改数据位置，以便迁移与备份。

验收标准：

- Given 便携版（exe 同目录存在 `portable_data/`），When 用户整体移动目录，Then 所有设置、收藏、备份随之迁移且无需重新配置
- Given 安装版，When 用户在设置中更改数据位置，Then 数据完整迁移到新位置并更新指向（迁移失败自动回滚）
- 导出格式为单一归档文件（含清单与校验），导入时校验版本兼容性

### FR-06 系统集成（P1）

作为用户，我想要开机自启、托盘运行、中英文界面、操作音效，并能检查新版本，以便日常使用顺手。

- 开机自启：Windows 注册表 Run 键写入/移除，开关即时生效
- 托盘：关闭窗口默认最小化到托盘（可配置直接退出）；托盘菜单含常用操作
- 中英文界面：i18n 资源热切换；操作音效可独立开关与调音量
- 检查新版本：启动时静默检查 + 手动检查，提示但不强制升级

### FR-07 收藏与置顶（P2）

作为用户，我想要保存长期使用的内容并把最常用的放在前面、拖拽即可调整顺序，以便高频内容触手可及。

- 适用于：播放器条目、脚本条目、常用文本片段
- 置顶优先于普通排序；拖拽顺序持久化

### FR-08 备注与编辑（P2）

作为用户，我想要为内容写容易辨认的说明，也能新增、修改常用文本，且已捕获的原始内容仍可恢复，以便放心修改。

- 条目备注自由文本；常用文本片段（snippets）可新增/编辑，历史版本保留可恢复

### FR-09 uosc 脚本深度支持（P1）

作为 uosc 用户，我想要对 uosc 及其生态脚本（uosc、console、统计等配套）做专项管理，以便充分发挥 uosc 的 UI 能力。

验收标准：

- Given 目标播放器未安装 uosc，When 用户选择"安装 uosc"，Then uosc 主脚本与配套依赖（ttypescript 字体探测可选）、`script-opts/uosc.conf` 一并就位，且 input.conf 合并 uosc 推荐按键（冲突时提示）
- Given uosc 已安装，When 用户在管理页调整元素显隐（顶栏/底栏/进度条/按钮组）与 `uosc.conf` 常用项（主题色、缩放、proximity），Then 修改写入 uosc.conf 且提供播放器内实时预览指引
- Given uosc 有新版本（Git 源），When 用户点击更新，Then 仅更新脚本本体，用户自定义 conf 不被覆盖

### FR-10 皮肤 UI 管理（P1）

作为用户，我想要统一管理 MPV 的 UI 皮肤（uosc 主题、OSC 替代皮肤如 ModernX、图标与配色方案），以便一键换装、所见即所得。

验收标准：

- Given 皮肤库中存在某 OSC 皮肤（如 modernx、uosc 主题包），When 用户一键应用，Then 冲突的旧 OSC（如内置 osc.lua）被禁用（`osc=no`）而非删除，皮肤文件就位，可一键回退
- Given 用户切换皮肤，When 打开播放器，Then 新皮肤生效且原皮肤配置保留（多皮肤共存、随时切回）
- 皮肤预览：列表展示皮肤截图/配色卡（本地截图或皮肤仓库自带预览图，无图则显示配色块）

### FR-11 配置文件冲突检测（P1）

作为用户，我想要在编辑 input.conf 和各类 conf 时自动检测冲突，以便在保存前发现按键重复绑定与键值冲突。

验收标准：

- Given input.conf 中同一按键被绑定多次，When 用户打开编辑器或修改绑定，Then 冲突项高亮并列出所有冲突行，支持一键跳转与选择保留哪一条
- Given input.conf 中同一按键绑定了不同命令（含 uosc 等脚本推荐的按键合并来源），When 检测运行，Then 按「来源 + 按键」分组展示冲突，来源可追溯（mpv 内置 / uosc / 用户自定义）
- Given mpv.conf 或脚本 conf 中同一键被多来源重复定义（如主 conf 与脚本 conf 的同键不同值），When 用户编辑涉及该键，Then 提示实际生效值（mpv 的覆盖规则：后加载/脚本级覆盖）与冲突来源
- Given 用户忽略冲突保存，Then 保留原样写入且不报错，但列表持续标红提醒（不阻塞用户）

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 冷启动 ≤ 2s（检测扫描后台化）；检测扫描不阻塞 UI |
| 体积 | 单二进制 + 资源，安装包 ≤ 30MB（目标值，待实测校准） |
| 平台 | Windows 优先（注册表/文件关联依赖 Win32 API）；macOS/Linux 后续评估 |
| 无障碍 | 对比度满足 WCAG 2.1 AA；键盘可达 |
| 安全 | 写注册表/文件系统操作前备份；导入数据做校验 |

## 5. 成功指标（定义，数值待上线后校准）

- **北极星**：周活跃用户的"跨包同步"使用次数
- 激活：新用户 10 分钟内完成「检测到播放器 → 完成 1 项配置」的比例
- 留存：次周留存率（目标基线待定）

## 6. 范围外（明确不做）

- 视频播放功能本身（交给 mpv）
- 在线脚本市场（P2 之后再议，先做本地 + Git 源）
- 非 MPV 内核播放器（PotPlayer、VLC 等）
