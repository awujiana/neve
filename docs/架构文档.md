# Névé 架构文档

> 版本：v0.5 | 状态：随代码演进 | 最后更新：2026-11-05
> 配套文档：[设计文档](./设计文档.md) · [UI 设计规范](./UI设计规范.md)

## 1. 总体架构

纯 Rust 单进程桌面应用，GPUI 原生 GPU 渲染，无 WebView。核心逻辑（`core`）与 UI（`ui`）严格分层，core 不依赖 gpui，可独立测试与复用。

```
┌─────────────────────────────────────────────┐
│                   ui (gpui)                 │
│   主窗口 / 托盘 / 主题引擎 / i18n / 音效      │
├─────────────────────────────────────────────┤
│                 core（纯 Rust）              │
│  players │ packages │ scripts │ config │    │
│  assoc   │ store     │ sync    │ backup     │
├─────────────────────────────────────────────┤
│              platform（平台适配）             │
│  winreg │ 关联注册 │ 自启动 │ 数据目录定位     │
└─────────────────────────────────────────────┘
```

### 依赖方向

```
ui ──> core ──> platform
        │
        └── 不依赖 ui；platform 不依赖 core
```

`ui` 内部再分两层：`ui::theme` 只依赖组件库主题类型；`ui` 页面模块只依赖 `core` 的公开接口与 `ui::theme` 投影后的语义色，不直接读配置字节，也不硬编码颜色。

## 3. 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| UI 框架 | GPUI 0.2 | 纯 Rust、GPU 渲染、单二进制；代价是生态年轻（风险见 §6） |
| 注册表访问 | winreg 0.56 | 轻量、事实标准，仅 Windows 编译（`cfg(windows)`） |
| 托盘 | `tray-icon`（候选） | GPUI 无内置托盘；该 crate 成熟且跨平台 |
| 音效 | `rodio`（候选） | 纯 Rust 音频播放，操作音效体积极小 |
| i18n | `rust-i18n` 或 Fluent（候选） | 中英文资源文件，运行时热切换 |
| 配置解析 | 自研 conf 解析器（mpv.conf 语法简单：key=value + 注释） | 避免引入重依赖；保留注释与顺序是硬需求 |
| 数据格式 | JSON（store）+ 原样文本（conf 备份） | store 需要结构化；conf 备份必须字节级可恢复 |

## 4. 数据存储设计

### 4.1 数据目录定位（FR-05）

```
便携模式判定：exe 同目录存在 portable_data/
├─ 便携版：  <exe_dir>/portable_data/        ← 随目录整体移动
└─ 安装版：  %APPDATA%/neve/                 ← 可在设置中迁移到自定义位置
            迁移位置记录于注册表 HKCU\Software\Neve\DataDir（安装版）
```

数据目录结构：

```
<data_dir>/
├─ settings.json          主题模式/外观/语言/音效/托盘等应用设置
├─ store.json             收藏、置顶、拖拽顺序、备注、常用文本片段
├─ snippets/              常用文本片段历史版本（原始内容可恢复）
├─ backups/               conf/脚本同步操作的时间戳备份
└─ cache/                 检测缓存、下载缓存
```

UI 主题的初始令牌与默认值草案保存在 `config/ui-theme.toml`，仅作为设计参考；运行时设置写入用户数据目录的 `settings.json`。该 TOML 文件当前不是程序已加载的资源。主题模式采用 `system | light | dark`，明确区分系统跟随与用户覆盖；界面组件从语义令牌取色，避免各页面维护独立色值。液态玻璃的透明度、模糊半径和阴影属于呈现参数，须在目标平台实测后定稿，并提供不透明回退。

### 4.2 备份与恢复（FR-03/08）

所有对播放器目录的写操作（脚本同步、conf 编辑、文件关联）遵循：

1. 写前备份：目标文件复制至 `backups/<操作>/<时间戳>/`，保留元数据（来源包、操作类型）
2. 操作日志：JSONL 追加，记录 what/when/target/hash
3. 恢复：UI 提供按操作批次回滚；「已捕获的原始内容仍可恢复」由此保证

## 5. 关键流程

### 5.1 播放器检测（已实现）

```
启动 → 三路并发扫描（路径/注册表/PATH）
     → canonicalize 去重合并
     → 配置目录补全（portable_config → %APPDATA%）
     → DetectedPlayer[] → ui 渲染
TODO：扫描移入后台任务，UI 先渲染骨架
```

### 5.2 脚本跨包同步（FR-03，规划）

```
源：包 X 的脚本 A（文件 + conf）
  → 差异计算（文件 hash / conf 逐行 diff）
  → 冲突策略（跳过/覆盖/双份保留，默认提示）
  → 目标写入前备份（core::backup）
  → 差异报告输出（新增/覆盖/跳过 清单）
```

### 5.3 文件关联（FR-06，规划，Windows）

```
Progid 注册：HKCU\Software\Classes\Neve.<ext>
  → shell\open\command 指向目标播放器 exe
  → 同时写 OpenWithProgids 加入"打开方式"列表
  → SHChangeNotify 通知 shell 刷新；全部写入前导出注册表备份
```

### 5.4 配置冲突检测（FR-11，已实现）

```
输入：input.conf 全量行（含 uosc 等脚本推荐按键来源标注）或 conf 键值表
  → 解析为 (键, 命令, 来源, 行号) 列表（conf 解析器 AST-lite，保留注释与行序）
  → 冲突分析：按键重复绑定 / 同键多来源不同值
  → 覆盖链计算：按 mpv 加载顺序（主 conf → 脚本 conf）标注实际生效值
  → 输出 ConflictReport[]（配置页「冲突与警告」区按「生效值 + 来源 + 行号」展示；仅提醒，不阻塞保存）
```

### 5.5 皮肤切换与预览（FR-10，预览已实现）

```
用户选择皮肤 S（uosc 主题 / modernx 等 OSC 皮肤）
  → 冲突检测：当前 OSC 提供者（内置 osc / uosc / 其他皮肤）
  → 旧提供者软禁用（mpv.conf 写 osc=no 或移出 script-opts 启用列表），文件保留
  → 皮肤文件与 conf 写入（写前走 core::backup）
  → 皮肤元数据（来源/版本/预览图）登记 store.json，支持随时切回
```

**皮肤页当前做到哪一步**：只做「读 + 预览」，不做写入。`core::skins` 从每个播放器的 `script-opts/uosc.conf` 读出 `color` / `opacity` / 布局相关选项，构造成 `SkinPalette` / `SkinOpacity` / `UoscLayout`，由 `ui::mpv_preview` 画成一张 16:9 的静态预览。切换皮肤（写 conf、软禁用旧 OSC）仍属规划。

预览的关键约束是**不许自造键**——详见 §5.12。

### 5.6 界面渲染与主题投影（已实现）

```
启动
  → gpui_kit::init(cx)                      组件库初始化（含主题全局量）
  → ui::apply_theme(cx, ThemeMode::Dark)    Theme::change(mode) 后 Theme::update 覆盖语义色
  → open_window(WindowOptions { titlebar: appears_transparent, … })
  → AppShell::render
        ├── 背景层  linear_gradient(150°, 两端色)（+ 可选自定义背景图）
        ├── render_title_bar   自绘标题栏：拖动区 + 主题开关 + 重新扫描 + 窗口控制
        └── 主体 h_flex
              ├── render_sidebar       常驻导航，选中态 = 背景 + 左标记 + 强调文字
              └── v_flex
                    ├── render_page_header   页标题 + 一句说明 + 工具行（策略 / 反馈）
                    └── div(flex_1, min_h_0, overflow_y_scrollbar)   内容区滚动容器
                          └── 概览页 / 播放器页 / 配置页 / 玻璃实验室 / 未接入页空状态
```

关键约束（改动时不得破坏）：

1. **根容器**必须 `size_full()` + `bg(theme.colors.background)` + `text_color(theme.colors.foreground)`。文字色沿样式树继承；缺少底色就会出现「白底浅色字」。
2. **滚动容器**必须 `flex_1()` + `min_h_0()` + `overflow_y_scrollbar()`（来自组件库 `ScrollableElement`，自带主题化滚动条）。
3. **颜色**一律取 `cx.theme().colors.*`。令牌在 `ui::theme` 投影，页面里不出现 `rgb(0x…)` 常量。
4. **组件库 `button_*` 字段不回落到 `primary`**，必须逐个显式赋值，否则浅色主题下主按钮会沿用内置近黑色。
5. **窗口控制按钮自绘**：`appears_transparent` 隐藏系统标题栏后，组件库 `TitleBar` 的 SVG 图标按钮在资源缺失时会变成不可见区域，故改用字形绘制。
6. **界面风格是液态玻璃**：卡片、标题栏、侧栏统一走 `ui::card()` / `ui::theme::glass(cx)`，不允许出现不透明填充。

### 5.7 液态玻璃的实现取舍

GPUI 不提供背景模糊，也不提供径向渐变，因此玻璃质感只能靠组合逼近。`ui::theme::Glass` 把材质抽象成一组令牌（背景渐变两端色、卡片表面、常驻容器表面、内高光边、外缘描边、投影色），深浅各一份；卡片由四层叠成：

| 层 | 作用 | 令牌 |
|---|---|---|
| 半透明填充 | 透出底层渐变，形成材质感 | `surface` |
| 1px 亮边 | 边缘折射高光 | `highlight` |
| 内侧 inset 高光 | 顶部一条细亮线，液态玻璃最关键的读感 | `highlight` |
| 向下柔和投影 | 把卡片从背景层抬起 | `shadow` |

背景柔光是这条路上唯一踩过坑的地方，两次失败尝试记录在此以免重犯：

- **单层圆**：边缘是硬边，透过半透明卡片看过去像瑕疵而不是光。
- **大半径阴影模糊**：把透明圆的 `blur_radius` 放大到 260px 看似能得到高斯衰减，实际因模糊采样精度不足出现**多边形棱边与网格接缝**，越大的半径越明显。
- **多层同心圆曾一度可行但已废弃**：64 层同心圆按 `(1-u)^2.2`（u 为归一化半径，外圈为 1）反解每层需要补的 alpha，能把外圈步进压到渲染噪声水平；但叠在半透底色上仍会显出**圆形轮廓**，观感像没擦干净的脏斑，因此整体移除，背景只留一层斜向渐变。结论：GPUI 里做不出可用的大面积柔光，别再尝试。

### 5.8 半透底色上的文字对比度

玻璃界面里「文字压在什么上」决定了它能不能用次级色，这是最容易踩空的一点：

| 文字位置 | 实测底色（纯黑桌面 / 浅色玻璃） | 可用色 | 实测对比度 |
|---|---|---|---|
| 页头说明（直接落在窗口底色） | 151/255 | `foreground`（主色，靠字号字重分层级） | 2.67 → 5.16 |
| 卡片辅助文字（落在 `surface` 面板） | 220/255 | `muted_foreground` | 9.04 |
| 底部状态栏（落在 `surface_strong`） | 250/255 | `muted_foreground` | 7.39 |

底色是半透的，合成值 ≈ 不透明度 × 渐变色：纯黑桌面上不透明度 0.72 只能把窗口底抬到 ≈152/255，正文压不住 AA；因此亮端把渐变取到纯白、下限提到 0.78（≈0.70 有效值）。下限只随明暗上升，深色端仍是 0.20——想要极透就把明暗拉到暗端。改动后用 `scripts/probe_contrast.py` 量一遍，正文要 ≥ 4.5:1。

### 5.9 交互件的几何约束

两个「看起来该能用、实际静默失效」的交互，根子都在**谁掌握渲染后的几何**：

| 交互 | 失效写法 | 根因 | 正确做法 |
|---|---|---|---|
| 拖动自绘标题栏 | `on_mouse_down` 里调 `window.start_window_move()` | `start_window_move` 在 `gpui-pre-windows` 未重写，是 `platform.rs` 的空默认实现；同时 `on_mouse_down` 让 gpui 把 `WM_NCLBUTTONDOWN` 判成已处理并返回 0，系统原生拖动也被掐断 | 拖动区 `.window_control_area(WindowControlArea::Drag)`，命中测试返回 `HTCAPTION`，由系统接管拖动 / 双击最大化 / 贴边分屏；该区域不挂鼠标按下监听器 |
| 手动拖滑杆 | 自己画 `Div` 轨道 + 点击监听器 | `Div` 拿不到渲染后的 `bounds`，无法把指针 x 换算成 0..100 的值 | 用组件库 `Slider` + `Entity<SliderState>`；状态在 paint 时记录 `bounds`，`update_value_by_position` 按 `round(value / step) * step` 量化 |

滑杆显式设 `min(0) / max(100) / step(1)`：轨道 180px，1% ≈ 1.8px，鼠标可逐 1% 拖动。`SliderEvent::Change` 在拖拽中连续发出（一次拖拽上百次），只改内存与主题；`Release` 才落盘。`cx.subscribe()` 返回 `#[must_use]` 的 `Subscription`，必须 `.detach()`。

`scripts/probe_drag.py` 用真实系统鼠标事件做回归：窗口位移 (120, 90)、不透明度 35→50%、明暗 86→40%、拖到 57% 精确命中（排除 step=5/10 的整档跳变）。轨道坐标由截图扫描自动定位，不写死：取每行亮度中位数当背景基准，找 150..220px 的连续横条再按 y 聚合。`find_tracks` 早期用「众数」当背景，被 180px 的轨道色反客为主，整条漏掉——渐变背景里浅色有好几种近似色，中位数才稳。

### 5.10 液态玻璃组件库

`src/ui/glass/` 把玻璃从页面里散落的样式拼装收成三层：

| 层 | 文件 | 职责 | 是否依赖 GUI 状态 |
|---|---|---|---|
| 参数 | `spec.rs` | `GlassSpec`（13 个数值/布尔量）、`GlassPreset` 五档、归一化与 `lerp` | 否 |
| 解析 | `resolve.rs` | `spec + theme::Glass 令牌 + 明暗比 → GlassLayers`（渐变两端色、描边、`Vec<BoxShadow>`） | 否，纯函数 |
| 组件 | `surface.rs` | `surface / card / panel / pill / preset_card`，返回 `Div` | 否，无状态 |

**为什么不把颜色放进参数**：`Root` 会用 `theme.tokens.background` 给整窗刷底色，只要有实色就会盖住 DWM 亚克力；组件库自己发明颜色等于绕过 `set_appearance` 的投影。参数层因此完全不含颜色，颜色只在解析层从令牌取。

**参考来源与映射**（详见 `docs/液态玻璃组件库.md`）：

| 参考 | 借来的东西 | GPUI 里的替代 |
|---|---|---|
| rxing365 WebGL | normal → UV 位移的折射语义 | 多条对称 `inset` 亮边，偏移由 `refraction_height` 驱动 |
| GlassExplorer (iOS 私有 `CAFilter`) | 内外折射 / `inputBleed*` / `inputBlur*0..4` 的分层参数与「参数探索器」形态 | 冷暖双色 inset 边近似色散；实验室页做实时调参 |
| Android Backdrop | `Backdrop → effects → highlight → shadow` 的分层；SDF 折射 shader | 直接照搬分层顺序；`resolve` 对应效果层 |
| yzrt 纯 CSS | 四条对称 inset 白边 + `:after` 45° 高光 | `BoxShadow { inset: true }`；线性渐变两个 stop 的 alpha 差 |
| `docs/源码.js` | 半透底 + 发丝亮边 + 收敛投影的配方 | 外投影 + 主亮线，透明度由令牌控制 |

GPUI 0.2 没有自定义 shader、`backdrop-filter`、径向渐变，线性渐变只有 2 个 color stop，因此这里做的是屏幕空间近似；真实背景模糊仍由 `Material` 映射到窗口层系统合成。组件库不提供大面积柔光能力（`AGENTS.md` 已记录大半径模糊会出现多边形棱边）。

`ui::card(cx)` 现在是 `glass::card(&GlassSpec::regular(), …)` 的薄封装；实验室页的参数只作用于预览卡，不写 `appearance.conf`、不改全局卡片。

### 5.11 配置工作区与逐行视图（已实现）

「能显示配置的注释」不能靠把 conf 读成 HashMap 再写回——真实整合包的一行里同时有缩进注释、对齐空格与行尾说明，结构化重写一定丢。配置层因此拆成两级：

| 级 | 载体 | 职责 |
|---|---|---|
| 语义层 | `ConfDoc.lines` / `InputDoc.lines` | `entries()` / `get()`、按键冲突、last-wins 生效判定 |
| 原文层 | `ConfDoc.raw_lines` / `InputDoc.raw_lines` | 展示与 `render()`；直接 `join(sep)`，保留缩进、对齐、行尾空格、CRLF |

`core::config::document` 是配置页的唯一数据源，产出 `PlayerConfigWorkspace → ConfigFileView → ConfigLineView`。`ConfigLineView` 一次给全：行号、类型（注释 / 配置项 / 按键 / 空行 / 小节 / 原文）、主文本、`inline_comment`、`doc_comment`（紧邻上方注释块最近一条说明）、`effective`（生效 / 被第 N 行覆盖 / 不适用）、缩进。

```
扫描：mpv.conf → input.conf → 根级其它 *.conf → script-opts/*.conf（含一层子目录）
     → 非 UTF-8 用 from_utf8_lossy 宽松展示，但标记 error 禁止编辑
     → 每行同时算语义与原文，render() 往返自检
     → 冲突报告给出「生效值 + 来源文件 + 行号」
```

两个容易踩空的语义边界：

1. **mpv.conf 不支持行内注释**。`vo=gpu-next # 视频输出驱动` 里的 `# 视频输出驱动` 实际会进入 value。`split_inline_comment()` 只在展示层把 ` #` 之后拆成 `inline_comment`，写入仍以原文行回写，不改变 mpv 看到的语义。
2. **注释掉的配置项不是配置项**。`#gpu-api=vulkan` 是整行注释，只能着色展示，不能进生效判定，更不能给它「编辑」按钮。

编辑闭环（`document::set_option_value`）：

```
点「编辑」（只有 editable && Active && 有 key 的行才有）
  → InputState 里改值
  → 只替换该生效行的 value 片段（缩进、等号后对齐、值后 padding、行尾说明原样）
  → BackupManager::backup_file() 写前备份
  → 落盘后用解析器做 render() 往返 + 结构化自检
  → 「撤回编辑（N）」按 operation_of(file) 找备份，canonical path 精确匹配后 restore()
```

混合行尾、非 UTF-8、往返自检失败的文件一律 `editable() == false`；编辑期间切换播放器或文件会取消保存，防止把值写到别的文件。输入框挂在 `Entity<InputState>` 上（组件库要自己记录渲染后的 bounds 才能处理光标与键盘事件）。所有颜色仍取 `cx.theme().colors.*`，卡片仍走 `ui::card()`。

### 5.12 uosc 预览的版式对齐依据（已实现）

皮肤页的预览不是「画个像播放器的图」，而是**照 uosc 源码逐条复刻**。第一版凭配置臆造，用户两次指出「与实际 uosc 样式不符」「这也不是 uosc 的 UI」，根因有三类，逐条修掉：

| 根因 | 表现 | 修法 |
|---|---|---|
| 自造配色键 | 造出 `menu_background` / `menu_foreground` / `menu_selection` / `timeline_track` / `time_current` 等 9 个 uosc 根本没有的键，预览是另一套配色 | `SkinPalette` 只保留 `main.lua` 里 `config_defaults.color` 的 10 个键，默认值取官方值 |
| 默认值不是官方值 | `timeline_size=12`（真实 30）、`controls_spacing=10`（真实 2）、`menu_item_height=44`（真实 36）、`border_radius=7`（真实 2） | 全部对齐 `uosc.conf` 默认值 |
| 控件名被压平 | `command:history:...` 解析成 `command`，预览里所有按钮同一个兜底字形 | `parse_controls()` 保留图标名参数与 `?tooltip` |

三条来自读源码的硬事实，直接决定画法：

1. **顶栏不是通栏底色**。`TopBar.lua` 在 `top_bar=no-border` 时只画左上「主标题胶囊（`bg` 底 + `bgt` 字）+ 可选副标题（`top_bar_alt_title_place=below` 时在下一行）」，右侧窗口按钮各画一个 `bg_size = size - margin` 的方块，`margin = floor((size - font_size)/4)`。
2. **控制条常态没有底色块**。`Controls.lua` 的 `background_opacity = self.active and 1 or config.opacity.controls`，而 uosc 默认 `opacity.controls=0`——所以实机是裸图标。放不下时 uosc **从中间往外左右交替隐藏**（`i = ceil(#layout/2 + 0.1)`，步长 `a * (a % 2 == 0 ? 1 : -1)`），`fit_controls()` 复刻了这条，实机才会出现「左右两簇、中间空」的形态。
3. **时间戳反色**。`Timeline.lua` 的 `draw_timeline_timestamp` 先用 `fgt` 画在 `\clip(前景区)` 内、再用 `bgt` 画在 `\iclip(前景区)` 内，即已播放段上白黑互换。章节是骑在 `fay - 1` 的小菱形，`diamond_radius = min(max(1, foreground_size * 0.8), chapter_size)`。

`controls=` 的条目语法是 `[<[!]{disposition}[,...]>]{element}[:{paramN}][#{badge}][?{tooltip}]`。两个坑：`command:{icon}:{cmd}` / `button:{icon}` / `cycle:{icon}:...` / `toggle:{icon}:{prop}` 的**第一个参数就是图标名**；`<video,audio>` 里的逗号是 OR 分组，`split(',')` 会把它拆坏——`split_control_list()` 因此做括号深度感知切分。

画布固定 16:9（720×405），按 `SkinKind` 分支：uosc 画顶栏 + 居中菜单 + 底部，内置 OSC 画左上标题 + 经典底部条。uosc 分支**不画字幕**（菜单 `opacity.menu=0.9` 居中，会和字幕糊成一片）。

GPUI 侧的能力缺口：无 `text_shadow`（查 `gpui-pre-0.3.9` 确认无此 API）、无自定义 shader、无 SVG filter、线性渐变只有 2 个 stop。因此图标用 `div` 几何形状拼（`fill` / `ring` / `glyph` 三个 helper），而不是加载 uosc 内嵌的 Material Icons——组件库 `gpui-kit-assets` 虽有完整 Lucide 图标目录，但需要注册 `AssetSource`，`gpui_kit::application()` 未自动挂载。

**验证方式**：用同一份 `portable_config` 启动真实 mpv（`mpv.exe v.webp --pause --image-display-duration=inf --force-window=yes --ontop=yes --geometry=900x520+80+80`）实机观察，基准截图归档为 `docs/screenshots/uosc-real.png`。预览改动必须对着这张图复核，不许凭配置想象。

### 5.13 滤镜切换与备份同步（已实现）

**滤镜切换只做注释 / 取消注释**。`core::filters` 把三类东西收成一张清单：`input.conf` 里的滤镜开关命令（`FilterKind::VideoFilter`）、`shaders/` 下的 GLSL（`Shader`）、`mpv.conf` 里的 profile 配置组（`Profile`）。切换走 `toggle_line()` / `toggle_profile()`——在行首加 / 去 `# `，**不改命令本身**，因此行号、快捷键、命令原文都还能给用户核对。

```
点开关
  → BackupManager::backup_file() 写前备份
  → 行首加 / 去 "# "（字节级只动 2 字节）
  → 重新扫描该文件，刷新「当前启用」计数
  → 页面顶部提示「已停用（已备份，可在「备份与同步」页撤回）」
```

不重写命令的理由和 §5.11 一致：真实整合包的 `input.conf` 里有对齐空格、行尾说明、条件前缀，任何结构化重写都会丢。实测一次切换后文件从 `53646` 字节变成 `53648` 字节，只多出 `# `。

**备份与同步页**是所有这些写操作的出口。`core::backup` 的 `list_operations()` / `list_all()` 按操作分组给出备份记录，`restore()` 前会**再备份一次当前文件**（否则撤回本身不可撤回）。跨整合包同步给出「源 / 目标 / 脚本」三行选择器 + 「生成同步计划」，**先生成计划再执行**，计划里列出新增 / 一致 / 冲突三类，避免盲写。

## 6. 风险与缓解

| 风险 | 影响 | 应对 |
|---|---|---|
| GPUI 0.2 API 不稳定 | 升级破坏性变更 | core 与 gpui 完全隔离，UI 层薄封装；锁版本升级前全量回归 |
| GPUI 无内置托盘 | FR-06 受阻 | 引入 tray-icon 独立线程，与 GPUI 事件桥接；验证失败则降级为"最小化到任务栏" |
| 注册表写操作风险 | 用户系统损坏 | 只写 HKCU；写前导出 .reg 备份；文件关联优先走 OpenWithProgids 而非抢默认 |
| conf 解析破坏用户手工注释 | 体验灾难 | 解析器保留原始行序与注释，仅修改目标键所在行（AST-lite 方案） |
| 同步覆盖用户自定义脚本 | 数据丢失 | 强制走 core::backup；冲突默认提示而非静默覆盖 |
| 多皮肤/OSC 提供者冲突（内置 osc vs uosc vs modernx） | 播放器 UI 异常重复渲染 | 单一提供者原则：切换皮肤时软禁用其他 OSC（mpv.conf `osc=no`），永不删除用户文件 |
| uosc 预览与实机不符 | 用户以为功能是假的 | 预览只许用 uosc 真实存在的键与官方默认值；改版式前先启动真实 mpv 对照 `docs/screenshots/uosc-real.png`（见 §5.12） |
