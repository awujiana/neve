# Névé 架构文档

> 版本：v0.5 | 状态：随代码演进 | 最后更新：2026-11-03
> 配套文档：[设计文档](./设计文档.md) · [UI 设计规范](./UI设计规范.md)

## 1. 总体架构

纯 Rust 单进程桌面应用，GPUI 原生 GPU 渲染，无 WebView。核心逻辑（`core`）与 UI（`ui`）严格分层，core 不依赖 gpui，可独立测试与复用。

```
┌─────────────────────────────────────────────┐
│                   ui (gpui)                 │
│   主窗口 / 托盘 / 主题引擎 / i18n / 音效      │
├─────────────────────────────────────────────┤
│                 core（纯 Rust）              │
│  players │ packages │ scripts │ config │    │
│  assoc   │ store     │ sync    │ backup     │
├─────────────────────────────────────────────┤
│              platform（平台适配）             │
│  winreg │ 关联注册 │ 自启动 │ 数据目录定位     │
└─────────────────────────────────────────────┘
```

### 依赖方向

```
ui ──> core ──> platform
        │
        └── 不依赖 ui；platform 不依赖 core
```

`ui` 内部再分两层：`ui::theme` 只依赖组件库主题类型；`ui` 页面模块只依赖 `core` 的公开接口与 `ui::theme` 投影后的语义色，不直接读配置字节，也不硬编码颜色。

## 3. 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| UI 框架 | GPUI 0.2 | 纯 Rust、GPU 渲染、单二进制；代价是生态年轻（风险见 §6） |
| 注册表访问 | winreg 0.56 | 轻量、事实标准，仅 Windows 编译（`cfg(windows)`） |
| 托盘 | `tray-icon`（候选） | GPUI 无内置托盘；该 crate 成熟且跨平台 |
| 音效 | `rodio`（候选） | 纯 Rust 音频播放，操作音效体积极小 |
| i18n | `rust-i18n` 或 Fluent（候选） | 中英文资源文件，运行时热切换 |
| 配置解析 | 自研 conf 解析器（mpv.conf 语法简单：key=value + 注释） | 避免引入重依赖；保留注释与顺序是硬需求 |
| 数据格式 | JSON（store）+ 原样文本（conf 备份） | store 需要结构化；conf 备份必须字节级可恢复 |

## 4. 数据存储设计

### 4.1 数据目录定位（FR-05）

```
便携模式判定：exe 同目录存在 portable_data/
├─ 便携版：  <exe_dir>/portable_data/        ← 随目录整体移动
└─ 安装版：  %APPDATA%/neve/                 ← 可在设置中迁移到自定义位置
            迁移位置记录于注册表 HKCU\Software\Neve\DataDir（安装版）
```

数据目录结构：

```
<data_dir>/
├─ settings.json          主题模式/外观/语言/音效/托盘等应用设置
├─ store.json             收藏、置顶、拖拽顺序、备注、常用文本片段
├─ snippets/              常用文本片段历史版本（原始内容可恢复）
├─ backups/               conf/脚本同步操作的时间戳备份
└─ cache/                 检测缓存、下载缓存
```

UI 主题的初始令牌与默认值草案保存在 `config/ui-theme.toml`，仅作为设计参考；运行时设置写入用户数据目录的 `settings.json`。该 TOML 文件当前不是程序已加载的资源。主题模式采用 `system | light | dark`，明确区分系统跟随与用户覆盖；界面组件从语义令牌取色，避免各页面维护独立色值。液态玻璃的透明度、模糊半径和阴影属于呈现参数，须在目标平台实测后定稿，并提供不透明回退。

### 4.2 备份与恢复（FR-03/08）

所有对播放器目录的写操作（脚本同步、conf 编辑、文件关联）遵循：

1. 写前备份：目标文件复制至 `backups/<操作>/<时间戳>/`，保留元数据（来源包、操作类型）
2. 操作日志：JSONL 追加，记录 what/when/target/hash
3. 恢复：UI 提供按操作批次回滚；「已捕获的原始内容仍可恢复」由此保证

## 5. 关键流程

### 5.1 播放器检测（已实现）

```
启动 → 三路并发扫描（路径/注册表/PATH）
     → canonicalize 去重合并
     → 配置目录补全（portable_config → %APPDATA%）
     → DetectedPlayer[] → ui 渲染
TODO：扫描移入后台任务，UI 先渲染骨架
```

### 5.2 脚本跨包同步（FR-03，规划）

```
源：包 X 的脚本 A（文件 + conf）
  → 差异计算（文件 hash / conf 逐行 diff）
  → 冲突策略（跳过/覆盖/双份保留，默认提示）
  → 目标写入前备份（core::backup）
  → 差异报告输出（新增/覆盖/跳过 清单）
```

### 5.3 文件关联（FR-06，规划，Windows）

```
Progid 注册：HKCU\Software\Classes\Neve.<ext>
  → shell\open\command 指向目标播放器 exe
  → 同时写 OpenWithProgids 加入"打开方式"列表
  → SHChangeNotify 通知 shell 刷新；全部写入前导出注册表备份
```

### 5.4 配置冲突检测（FR-11，规划）

```
输入：input.conf 全量行（含 uosc 等脚本推荐按键来源标注）或 conf 键值表
  → 解析为 (键, 命令, 来源, 行号) 列表（conf 解析器 AST-lite，保留注释与行序）
  → 冲突分析：按键重复绑定 / 同键多来源不同值
  → 覆盖链计算：按 mpv 加载顺序（主 conf → 脚本 conf）标注实际生效值
  → 输出 ConflictReport[]（编辑器高亮 + 冲突面板；仅提醒，不阻塞保存）
```

### 5.5 皮肤切换（FR-10，规划）

```
用户选择皮肤 S（uosc 主题 / modernx 等 OSC 皮肤）
  → 冲突检测：当前 OSC 提供者（内置 osc / uosc / 其他皮肤）
  → 旧提供者软禁用（mpv.conf 写 osc=no 或移出 script-opts 启用列表），文件保留
  → 皮肤文件与 conf 写入（写前走 core::backup）
  → 皮肤元数据（来源/版本/预览图）登记 store.json，支持随时切回
```

### 5.6 界面渲染与主题投影（已实现）

```
启动
  → gpui_kit::init(cx)                      组件库初始化（含主题全局量）
  → ui::apply_theme(cx, ThemeMode::Dark)    Theme::change(mode) 后 Theme::update 覆盖语义色
  → open_window(WindowOptions { titlebar: appears_transparent, … })
  → AppShell::render
        ├── 背景层  linear_gradient(150°, 两端色)（+ 可选自定义背景图）
        ├── render_title_bar   自绘标题栏：拖动区 + 主题开关 + 重新扫描 + 窗口控制
        └── 主体 h_flex
              ├── render_sidebar       常驻导航，选中态 = 背景 + 左标记 + 强调文字
              └── v_flex
                    ├── render_page_header   页标题 + 一句说明 + 工具行（策略 / 反馈）
                    └── div(flex_1, min_h_0, overflow_y_scrollbar)   内容区滚动容器
                          └── 概览页 / 播放器页 / 未接入页空状态
```

关键约束（改动时不得破坏）：

1. **根容器**必须 `size_full()` + `bg(theme.colors.background)` + `text_color(theme.colors.foreground)`。文字色沿样式树继承；缺少底色就会出现「白底浅色字」。
2. **滚动容器**必须 `flex_1()` + `min_h_0()` + `overflow_y_scrollbar()`（来自组件库 `ScrollableElement`，自带主题化滚动条）。
3. **颜色**一律取 `cx.theme().colors.*`。令牌在 `ui::theme` 投影，页面里不出现 `rgb(0x…)` 常量。
4. **组件库 `button_*` 字段不回落到 `primary`**，必须逐个显式赋值，否则浅色主题下主按钮会沿用内置近黑色。
5. **窗口控制按钮自绘**：`appears_transparent` 隐藏系统标题栏后，组件库 `TitleBar` 的 SVG 图标按钮在资源缺失时会变成不可见区域，故改用字形绘制。
6. **界面风格是液态玻璃**：卡片、标题栏、侧栏统一走 `ui::card()` / `ui::theme::glass(cx)`，不允许出现不透明填充。

### 5.7 液态玻璃的实现取舍

GPUI 不提供背景模糊，也不提供径向渐变，因此玻璃质感只能靠组合逼近。`ui::theme::Glass` 把材质抽象成一组令牌（背景渐变两端色、卡片表面、常驻容器表面、内高光边、外缘描边、投影色），深浅各一份；卡片由四层叠成：

| 层 | 作用 | 令牌 |
|---|---|---|
| 半透明填充 | 透出底层渐变，形成材质感 | `surface` |
| 1px 亮边 | 边缘折射高光 | `highlight` |
| 内侧 inset 高光 | 顶部一条细亮线，液态玻璃最关键的读感 | `highlight` |
| 向下柔和投影 | 把卡片从背景层抬起 | `shadow` |

背景柔光是这条路上唯一踩过坑的地方，两次失败尝试记录在此以免重犯：

- **单层圆**：边缘是硬边，透过半透明卡片看过去像瑕疵而不是光。
- **大半径阴影模糊**：把透明圆的 `blur_radius` 放大到 260px 看似能得到高斯衰减，实际因模糊采样精度不足出现**多边形棱边与网格接缝**，越大的半径越明显。
- **多层同心圆曾一度可行但已废弃**：64 层同心圆按 `(1-u)^2.2`（u 为归一化半径，外圈为 1）反解每层需要补的 alpha，能把外圈步进压到渲染噪声水平；但叠在半透底色上仍会显出**圆形轮廓**，观感像没擦干净的脏斑，因此整体移除，背景只留一层斜向渐变。结论：GPUI 里做不出可用的大面积柔光，别再尝试。

### 5.8 半透底色上的文字对比度

玻璃界面里「文字压在什么上」决定了它能不能用次级色，这是最容易踩空的一点：

| 文字位置 | 实测底色（纯黑桌面 / 浅色玻璃） | 可用色 | 实测对比度 |
|---|---|---|---|
| 页头说明（直接落在窗口底色） | 151/255 | `foreground`（主色，靠字号字重分层级） | 2.67 → 5.16 |
| 卡片辅助文字（落在 `surface` 面板） | 220/255 | `muted_foreground` | 9.04 |
| 底部状态栏（落在 `surface_strong`） | 250/255 | `muted_foreground` | 7.39 |

底色是半透的，合成值 ≈ 不透明度 × 渐变色：纯黑桌面上不透明度 0.72 只能把窗口底抬到 ≈152/255，正文压不住 AA；因此亮端把渐变取到纯白、下限提到 0.78（≈0.70 有效值）。下限只随明暗上升，深色端仍是 0.20——想要极透就把明暗拉到暗端。改动后用 `scripts/probe_contrast.py` 量一遍，正文要 ≥ 4.5:1。



| 风险 | 影响 | 应对 |
|---|---|---|
| GPUI 0.2 API 不稳定 | 升级破坏性变更 | core 与 gpui 完全隔离，UI 层薄封装；锁版本升级前全量回归 |
| GPUI 无内置托盘 | FR-06 受阻 | 引入 tray-icon 独立线程，与 GPUI 事件桥接；验证失败则降级为"最小化到任务栏" |
| 注册表写操作风险 | 用户系统损坏 | 只写 HKCU；写前导出 .reg 备份；文件关联优先走 OpenWithProgids 而非抢默认 |
| conf 解析破坏用户手工注释 | 体验灾难 | 解析器保留原始行序与注释，仅修改目标键所在行（AST-lite 方案） |
| 同步覆盖用户自定义脚本 | 数据丢失 | 强制走 core::backup；冲突默认提示而非静默覆盖 |
| 多皮肤/OSC 提供者冲突（内置 osc vs uosc vs modernx） | 播放器 UI 异常重复渲染 | 单一提供者原则：切换皮肤时软禁用其他 OSC（mpv.conf `osc=no`），永不删除用户文件 |

## 7. 测试策略

- 冒烟测试：`detect_players_runs` 等已随 M1 落地
- 集成测试：临时目录模拟便携/安装版数据布局（CI 可跑）
- 手动验收：每里程碑对照设计文档 Given-When-Then 逐条勾验
